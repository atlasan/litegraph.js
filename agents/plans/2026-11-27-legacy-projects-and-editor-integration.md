# Legacy project compatibility and 3D editor integration

> **Date** 2026-11-27 · **Kind** plan · **Status** proposed · **Base** `LG/dev_plan` @ `f80ca96`

Use WebGLStudio as the first downstream acceptance target for [LiteGraph's legacy compatibility decision](../memories/decisions/0008-legacy-compatibility-scope.md). Keep existing projects usable as the editors gain current LiteGraph authoring and diagnostics. Develop WebGLStudio and nunuStudio in parallel once each has a tested way to load and run graphs with the same LiteGraph build.

## Starting points

- **LiteGraph.** [Tier 4 step 15](2026-11-25-next-priorities-after-0.18.0-dev.2.md#tier-4-other-projects) already calls for a classic-script browser bundle. The ESM and CJS entries, per-document execution models, and the `legacy` model give the compatibility work explicit entry points.
- **WebGLStudio `e4e3ab9`.** A Chromium comparison used the bundled LiteGraph as the control and a temporary module loader with legacy globals for LiteGraph `f5c5437`. The adapter restored scene updates, inline and external graphs, scene-node drops, FX texture output, and execution of a saved scene in the desktop player. It exposed keydown re-entry and an extra inspector panel on double-click. Drawing on the shared WebGL canvas reached an undefined `spacing` variable in WebGLStudio's Canvas2DtoWebGL shim. The shipped default material graph produced no shader code with either bundle. Mobile and exported packages were outside the probe.
- **Reverse compatibility.** A graph saved with a current `basic/const` in `ON_REQUEST` kept its links in the bundled runtime but produced no value. Changing that fixture's constant to `ALWAYS` restored its value. This proves a compatibility case for the fixture. Other pulled nodes can depend on evaluation order, demand, or side effects.
- **nunuStudio `threejs-r187` @ `fa2de363`.** The current checkout has an Escher-based `NodeScript` and a Playwright editor/runtime harness. `origin/first_litegraph` @ `17fd654d` has an earlier `LiteGraphScript`, a loader case, a graph editor tab and object-position nodes. Its serialized `object.graph` and object-movement example are starting points for fixtures. The prototype has yet to be exercised against the current checkout.

## Compatibility and sequencing

- Steps 2 and 4 can proceed in parallel after the build and fixture work in step 1 starts. Step 3 can proceed independently of nunuStudio. The shared feature in step 5 uses the working scene bindings from both.
- Treat loading legacy graphs, exporting to an older runtime, and sharing behavior between editors as three independently tested contracts. Test values, lifecycle events, and scene effects in addition to file structure.
- Keep LiteGraph core independent of LiteScene, LiteGUI and three.js APIs. WebGLStudio owns its host fixes, shader material integration and export packaging. nunuStudio owns its scene and three.js bindings. Reuse the LiteGraph browser checks and the nunuStudio Playwright harness for downstream coverage.
- Use the [compatibility charter](../../docs/compatibility.md) for shared runtime and document semantics. A compatibility conversion can lower a feature only when the target preserves its behavior. Otherwise, surface the issue before export.
