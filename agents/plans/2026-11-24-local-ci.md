# Local CI with proof reports, GitHub CI kept but gated off

> **Date** 2026-11-24 · **Kind** plan · **Status** accepted · **Base** `LG/dev` @ `f944f3d` · **Branch** `LG/dev_HMD_ci`

A local CI runner, `tools/ci/ci.mjs` (`npm run ci:local`, `lg ci`), checks out any ref into a clean throwaway clone under the git-ignored `.lg/ci/`, runs the same steps as the GitHub workflow (and optional extra steps), runs several refs in parallel, and writes a proof report (JSON, Markdown, logs with hashes, a one-line summary for commit trailers, git notes and PR comments). The GitHub workflow comes back, gated off by a repository variable, with a switch command. This refines roadmap decision D10 (user, 2026-11-24): GitHub CI disabled but maintained, local CI as the proof.

## Context

- `f944f3d` removed `.github/workflows/validate.yml` and added `npm run check:all`.
- The workflow ran on Node 22: `npm ci --ignore-scripts`, `npm run check`, `git diff --exit-code --stat -- build build_node`.
- Release checks so far were done by hand (clean clone, `npm audit`, `npm pack` install, ComfyUI probes), see the [0.18.0-dev.2 release record](../executions/2026-11-23-pre-release-0.18.0-dev.2.md).
- The launcher (`tools/lg/`) keeps its state in `.lg/`.

## Decisions taken here

- **Gate:** the job runs only when the repository variable `LG_GITHUB_CI` is `on` (`if: vars.LG_GITHUB_CI == 'on'`); `workflow_dispatch` allows a manual run, which is also gated. Unset, every run is skipped (no runner minutes, the check shows as skipped, not failed). Other mechanisms considered: `gh workflow disable` (state hidden in the GitHub UI, not visible in the repo, and a manual run is impossible while disabled) and renaming the file (needs a commit and a push to switch). The variable needs no commit and is one command each way.
- **Checkout:** `git clone --local --no-checkout` of the main repository, then `checkout --detach <sha>`, in `.lg/ci/work/<run-id>/`. A clone, not a worktree, so nothing is registered in the main repository and a crashed run leaves no worktree entry. Objects are hard-linked, so it is fast.
- **Isolation:** each run has its own directory, `TMPDIR`, npm cache only shared (cacache is safe for concurrent use). The integration tests already use port 0 and `mkdtemp`; Jest in the main checkout must ignore `.lg/` so it does not run the copies.
- **Outward actions:** `github on|off` changes a repository setting, `--post` comments on a PR or issue; both are run only by the user or after the user's explicit yes. Notes go to `refs/notes/ci` locally and are never pushed by the tool.

## Scope

- In: the gated workflow and the switch; the runner (run, list, show, clean, github); report formats; optional steps `audit`, `pack`, `comfy`, `bun`; tests; docs and records.
- Out: running on GitHub; Windows and macOS runs; pushing notes; a scheduler.

## Risks and open questions

- A run takes the time of `npm run check` plus `npm ci` (about 2–3 minutes); parallel runs compete for CPU, so Jest timeouts could become flaky under load. `--jobs` defaults to 2.
- The report proves a run on this machine, not a reproducible build: it records the OS and runtime versions so a reader can judge.
