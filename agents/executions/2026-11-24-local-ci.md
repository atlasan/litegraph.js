## Design notes

- **Gate:** a repository variable, not `gh workflow disable` (state invisible in the repository, no manual run while disabled) or a renamed file (a commit and push per switch). Unset, the job is skipped: no minutes, no failing check.
- **Clone, not worktree:** `git clone --local` (hard-linked objects, 0.5 s) registers nothing in the main repository, so a crashed run leaves no worktree entry.
- **Parallel clashes checked:** the integration tests bind port 0 (`runner.test.mjs` reserves a free port with `listen(0)` and releases it; `runner-security.test.mjs` only parses Host/Origin strings, it binds nothing); the launcher tests set `LG_STATE_DIR` to `mkdtemp` folders; `check-build` uses a `mkdtemp` npm cache for `npm pack --dry-run`. Each run also gets its own `TMPDIR`. The shared npm cache (cacache) is safe for concurrent use. The one real clash was the main checkout's Jest finding the clones' tests under `.lg/`; Jest now ignores `.lg/`.
- **Steps' environment:** `CI=true` as on GitHub, `npm_*` variables from an outer `npm run` removed, no colour.
- **Bun is advisory:** `bun test tools/tests` fails one known case (`library-manager`, a `data:` import with top-level await; see the launcher record), so the step is reported but never fails a run.
- **`pack` check:** npm leaves empty `@socket.io/` and `@types/` folders for the omitted optional dependencies; the check counts packages, not folders (the first trial run failed on that).

## Left open

- The variable `LG_GITHUB_CI` is unset on GitHub, and stays so until the user runs `npm run ci:github -- on`. The workflow reaches GitHub only with the next push of `LG/dev` (user's decision).
- Windows and macOS runs: not tried (the runner uses `git`, `npm`, `node` and POSIX paths only through Node APIs; the fake-`gh` tests skip on Windows).
