## Architecture to preserve

`LiteGraph` is a singleton registry; `LGraph` owns execution/serialization, `LGraphNode` supplies node methods, `LGraphCanvas` handles browser interaction. `initialize()` wires classes, callback handling and LibraryManager after imports resolve. Standalone node classes receive base prototype descriptors during registration; inherited overrides must survive. Extensions use CallbackHandler and should remain compatible with direct callback assignments. ON_REQUEST and ancestor refresh behavior are fork-specific and need their own regression fixtures before upstream execution changes.

`build.py` concatenates a fixed ordered source list into six ESM variants and six CommonJS variants, enabling marked Node-only code in CJS output. It is a constrained custom bundler, not a general JavaScript module transformer. Runtime dependencies and browser-only nodes are environment-sensitive.

The runner has HTTP static/file-list routes, a WebSocket protocol, and one worker per workflow. The worker must own the executing graph. Browser preview and worker execution are separate states; successful command delivery is not successful graph execution. Workflows are trusted local programs: Node nodes can operate on files, processes and networks. The runner is a local development tool, not a sandbox or public multi-user service.

## Reproduced baseline defects

1. `npm test -- --runInBand`: 9 pass, 3 fail. Stale expectations for debug logging, prefixed warnings and the unregister error; mock/registry isolation also incomplete.
2. `npm run lint`: 55 errors, 1,906 warnings. This is a pre-existing repository-wide baseline, not a clean gate.
3. Requiring the full Node bundle returns the last network node's constructor instead of library exports. Embedded `module.exports = ...` overwrites the concatenated bundle; the builder also omits exported variables such as LiteGraph.
4. Builder subprocesses use `shell=True` with argument arrays, do not check status and may write empty minified outputs. Missing inputs are merely printed and ignored.
5. `runStep` accepts a node limit but executes every node in both branches.
6. Descriptor copying uses own-property checks and can shadow inherited custom methods.
7. Runner uses worker presence as execution status; ignores most worker acknowledgments; graph updates affect only a duplicate graph in the server; sync returns that duplicate; Stop All UI command is unhandled; unload is a fixed timer and retains preview state.
8. Runner client hardcodes ws://localhost:3000; filesystem/worker paths depend on process.cwd(); requested workflow paths are not confined to the workflow root.
9. Tester page loads independent source modules without reliable initialization, captures null class aliases, and is not served by `npm run editor`. Framework bypasses createNode and misses cleanup on failure.
